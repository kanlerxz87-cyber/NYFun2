Sources, rules and how to reproduce

The verification rules, the primary-source register, and the two scripts that turn canonical data into this site.

The rules this build follows

  1. One official source per row. MICHELIN Guide, a government page, or the venue's own site. Social platforms are used for links, never to establish a price or an hour.
  2. No inference. If a page does not state it, the cell is blank. Bands ($$–$$$$) are never converted to dollars; a "from" rate is never treated as a quote.
  3. Arithmetic is shown. A couple total is always 2 × the published per-person price, and hotel all-in totals show the tax formula used.
  4. Provenance is recorded per field. Each merged row carries a provenance object naming the session that supplied each value.
  5. Conflicts are published, not resolved silently. Disagreements go to data/conflicts.json and the Flagged page.
  6. Third-party is labelled. Review videos are marked as reviews; only accounts confirmed by the venue's own site are called official.

How this build is produced

research/canonical/*.json holds the pristine datasets from the research sessions. scripts/build_data.py merges the parallel kits into data/*.json under the rules above (idempotent — re-running cannot double-count). scripts/build_site.py renders these pages. scripts/verify.py checks links, source-per-row, and blank-implies-flag.

python3 scripts/verify.py
node --check assets/app.js

No build step, no dependencies, no trackers. GitHub Pages serves the repository root.
